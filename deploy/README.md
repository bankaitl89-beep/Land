# lead.php — приёмник заявок

Один файл. Лендинг остаётся статикой в трекере, токен лежит здесь, на сервере.

## Установка

1. Скопируй `lead.php` и `lead.config.example.php` туда же, где лежит лендинг.
2. Переименуй `lead.config.example.php` → `lead.config.php`, впиши токен и chat id.
3. Собери лендинг с адресом приёмника:

   ```
   NEXT_PUBLIC_LEAD_ENDPOINT="https://твой-домен/lead.php" npm run static
   ```

4. Проверь: отправь заявку с формы — должна прийти в Telegram и появиться строкой в `leads.log`.

## Что он делает

Порядок важен: **заявка пишется в лог раньше, чем что-либо может её отклонить.**
Ни бот, ни флуд, ни упавший Telegram не могут потерять строку. Telegram — это
уведомление, лог — это запись.

`leads.log`, по одному JSON на строку:

```json
{"at":"2026-09-16T12:00:00+00:00","name":"Иван Петров","email":"ivan@example.com",
 "lang":"ru","page":"https://lp/?c=1","ip":"1.2.3.4","ua":"...","flags":[]}
```

`flags` — почему заявка не дошла до Telegram:

| флаг | значение |
|---|---|
| (пусто) | всё хорошо, ушла в Telegram |
| `bot` | заполнено скрытое поле-ловушка |
| `no-name` / `bad-email` | не прошла проверку |
| `rate-limited` | больше 6 отправок с одного IP за минуту |

Боту в ответ всегда `200 ok` — иначе он просто научится не заполнять ловушку.

## Посмотреть заявки

```
tail -f leads.log                                  # в реальном времени
grep -c '"flags":\[\]' leads.log                   # сколько настоящих
grep -v '"flags":\[\]' leads.log                   # что отсеялось и почему
```

## Настройки

- `origins` — какие сайты могут сюда постить. По умолчанию `'*'`. Как узнаешь
  домен лендинга, впиши его: `['https://example.com']`.
- `limit` — отправок с одного IP в минуту, по умолчанию 6.
- `token` / `chat` пустые — заявки только пишутся в лог, без уведомлений. Это
  рабочий режим, не поломка.

## Требования

PHP 8 с `curl`. Больше ничего: ни composer, ни базы, ни фреймворка.
